## Final contract audit and local gate — 01/11

The four remaining data-contract boundaries were read through their current callers, DTOs, tests and failure containment. None has enough product semantics for a safe production implementation:

- CSV maps both `null`/`undefined` and an empty string to the same empty cell, while import uses `defval: ''`. The wire bytes contain no reversible distinction; a sentinel, schema sidecar or column-aware import policy must be chosen before code can preserve SQL NULL.
- Mongo row update/delete editing is deliberately rejected before strategy dispatch until a unique typed identity can be verified. Generic JSON insert and existing MQL mutation paths remain available, but current DTOs define no Extended JSON envelope or BSON subtype-preserving write contract; claiming ObjectId/Decimal128/Binary round trips would invent a public wire format.
- Redis update uses `SET`, which can replace type and TTL, while insert overwrite, TTL-copy and missing-key behavior are not defined. SCAN paging is intentionally bounded but is not a stable snapshot under concurrent keyspace mutation. No TTL or snapshot policy was inferred.
- Migration can commit a partial batch before an ambiguous failure. The persisted stage guard and native regressions intentionally reject replay because there is no checkpoint, idempotency key or whole-transfer rollback contract.

No production source was changed for these four boundaries. Current behavior is not uniformly fail-closed: Mongo row update/delete and migration replay are contained, but CSV remains lossy for NULL versus empty and Redis insert still reaches `SET`, which may overwrite an existing key and remove its TTL. The safe action in this task is to expose those retained limits and require an explicit product decision, not to guess a sentinel, BSON envelope, overwrite/TTL policy or retry algorithm.
