## Backend full-stack E2E — Windows/PowerShell

Môi trường dưới đây chỉ dùng dữ liệu tổng hợp; cần Docker Desktop, dependencies đã cài và Prisma client đã generate. Suite R03 thêm MongoDB 7 và MySQL 8.4 qua overlay `compose.r03.yml`; full command cần cả hai file compose, với cổng loopback 15432/16379/17017/13306. Chạy tại gốc repo:

```powershell
docker compose -f server/test/compose.e2e.yml -f server/test/compose.r03.yml up -d --wait
if ($LASTEXITCODE -ne 0) { throw 'Fixture startup failed' }
$env:E2E_DATABASE_URL = 'postgresql://e2e:e2e-local-only@127.0.0.1:15432/data_explorer_e2e'
$env:E2E_REDIS_URL = 'redis://127.0.0.1:16379/15'
$env:DATABASE_URL = $env:E2E_DATABASE_URL
Push-Location server
try {
  node -e "require('./test/e2e-environment.cjs').createE2eEnvironment(process.env)"
  if ($LASTEXITCODE -ne 0) { throw 'Unsafe E2E environment' }
  npx.cmd prisma migrate deploy
  if ($LASTEXITCODE -ne 0) { throw 'Fixture migration failed' }
  npm.cmd run test:e2e -- --detectOpenHandles
  if ($LASTEXITCODE -ne 0) { throw 'E2E gate failed' }
} finally {
  Pop-Location
  docker compose -f server/test/compose.e2e.yml -f server/test/compose.r03.yml down
}
```

Đọc exit code của từng lệnh; không tiếp tục migrate/test nếu setup lỗi. Compose dùng cổng bind loopback, project `data-explorer-e2e`, PostgreSQL/MongoDB/MySQL tmpfs và Redis không persist. Kiểm tra resource ownership trước khi dùng `down` nếu đã có container cùng project từ công việc khác. Linux dùng `npm`/`npx` và biến môi trường shell tương ứng, cùng URL fixture. Suite R03 chỉ gọi các cổng fixture cố định trên loopback, tạo user/table/function/database/key với định danh riêng rồi teardown; không thay bằng URL hoặc credential production.

Harness **không fallback** từ `DATABASE_URL`/`REDIS_URL` thường. Nó yêu cầu hai URL E2E chỉ rõ loopback, database `data_explorer_e2e`, Redis DB 15 và không query override; chỉ dùng resource fixture thuộc quyền kiểm soát của lượt test. Nó loại bỏ config thừa kế và chặn `.env` loader của Nest/Prisma. Mock chỉ áp dụng loader config; Prisma, PostgreSQL, Redis, auth guards, controllers và SQLite query đều chạy thật. Không gọi ngân hàng, mail hay AI provider.

Auth suite tạo hai user verified và một connection SQLite thật của B, kiểm tra truy cập hợp lệ trước khi yêu cầu user A bị deny. Limiter giữ nguyên 5/min; chỉ reset key limiter trong Redis fixture giữa các case, không chấp nhận 429 cho enumeration test. Không skip/early return khi setup/login thất bại. Teardown errors được trả về; không dùng `--forceExit`.

**Giới hạn quan trọng:** helper teardown đóng Redis client do cấu hình cache `store` legacy tạo ngoài lifecycle cache-manager v6 `stores`. Nó không chứng minh cache production đã nối Redis đúng; việc đó thuộc R10/R14. Full-stack ở đây không bao gồm Chromium truy cập server thật hay mọi engine database.
